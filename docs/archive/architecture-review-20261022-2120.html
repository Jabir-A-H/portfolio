Top recommendation

Start with the content query module.

It is the deepest leverage in the repo: every page currently reshapes raw content, four query functions are unused, and the content phase will add more views. One seam stabilizes grouping, counts, categories, and options before services and projects are rewritten. The project row and metadata candidates become smaller once this seam exists.

Also considered, not recommended

  • Theme module: the inline anti-FOUC script cannot import a shared module; the seam would be hypothetical.
  • Section rhythm module: pages use deliberate one-off spacing; a shared rhythm module would hide the composition.
  • Reveal implementation seam: real 50 kB home-bundle saving, but motion quality risk; revisit after content ships.
  • Portfolio filter hook: one caller; a seam would be hypothetical until a second filter exists.
